# Agent Note: Plan mode

Status: implemented — Claude Code's plan mode: the agent only looks around until the user approves its plan

## Problem

For a large change, the user wants to see and agree to the agent's approach before
anything is edited or run. Claude Code has plan mode for this: the agent (with
`EnterPlanMode`) or the user turns it on, the agent may then only read, and it presents
its plan with `ExitPlanMode`; the user approves it, optionally choosing how much the agent
may then do without asking, or sends it back. Lowering Kadence's permission level does not
do this: it turns every call into a prompt instead of keeping the agent to reading.

## Decision

- **A mode the runtime owns**, for the open conversation, in memory:
  `RuntimeAPI.set_plan_mode(on)` turns it on or off in any state with a conversation open;
  `PlanModeChanged(on)` follows a change, and `RuntimeSnapshot.plan_mode` holds it.
  Opening another conversation leaves it, as the conversation's grants are left.
- **What runs in it:** calls of read-only tools (`ToolSpec.read_only`) and the runtime
  built-ins that change nothing outside the conversation (`api.PLAN_MODE_TOOLS`: the todo
  list, questions, the mode's two tools, `wrap_up`, `TaskStop`, `ask_for_help`,
  `finish_goal`). Every other call is refused (`REFUSED`) before hooks and permissions,
  with a reason that tells the agent to present its plan with `ExitPlanMode`. The
  permission level still applies to the calls that run. While it is on, the system prompt
  says so (`PLAN_MODE_PROMPT`).
- **`EnterPlanMode`**, no parameters, as in Claude Code: turns the mode on.
- **`ExitPlanMode`**, parameter `plan` (markdown), as in Claude Code's tool before it read
  the plan from a file. Outside plan mode it is an error; in it, it emits
  `PlanProposed(call_id, plan)` and waits, as `AskUserQuestion` does (state
  `AWAITING_PERMISSION`, `RuntimeSnapshot.pending_plan`).
- **Answering:** `RuntimeAPI.resolve_plan(call_id, approve, feedback=None, permissions=None)`.
  Approval ends plan mode, after setting the permission level through `update_settings`
  when `permissions` is given; the result is the approved plan and the agent goes on in the
  same turn. Sent back, plan mode stays and the result quotes the user's feedback. A
  message sent while a plan waits sends it back, the message following the result as the
  user's own, as for a question; turning plan
  mode off approves it. `PlanResolved(call_id, approved, feedback)` follows; Stop ends the
  wait as cancelled, with `approved` None.
- **The desktop app:** "Plan mode" is the last entry of the permission picker under the
  message box, whose label reads "Plan mode" while it is on. A waiting plan is a card above
  the message box (`PlanApprovalCard`): the plan, **Approve**, **Approve and…** with the
  permission levels, and **Keep planning**; a reply typed instead sends it back with that
  reply.
- **Headless and remote:** the command and events go over the wire as they are.
- **KFM:** nobody approves a unit's plan, so KFM's Kadence harness approves it at once,
  keeping the unit's permissions, and reports the plan as what the unit said.

## Alternatives considered

- **The plan in a file the agent writes,** as Claude Code's newest `ExitPlanMode` reads it.
  The file must live outside the work folder, so writing it would need a permission
  exception for one path in plan mode, through the Tools module, and the review and the
  sandbox would ask about it. The `plan` parameter is the one models were trained on longest.
- **Plan mode as a permission level.** Permission levels are a saved setting for every
  conversation, and lowering them makes calls prompt rather than be refused, so the agent
  would keep asking to edit instead of planning.
- **Asking the user before `EnterPlanMode` takes effect,** as Claude Code does. Entering
  only narrows what the agent may do, and a third kind of wait would reach every frontend
  and KFM; the user leaves the mode from the picker at any time.
- **Subagents in plan mode** (Claude Code's read-only Explore agent). Kadence's subagent
  has all of the parent's tools, so `Agent` is refused like any call that changes things.

## Consequences

- The user can agree to an approach before anything changes, and the agent meets the
  tools it knows from Claude Code.
- An agent in plan mode cannot hand research to a subagent; it reads for itself.
- An agent in a Kadence duty that enters plan mode waits until the user approves, as it
  does for a question. In a KFM fleet it never waits.
- A plan approved "and" a looser level changes the setting for every conversation, as the
  picker does.
- Plan mode is gone after a restart; a plan that waited is interrupted with its call.
