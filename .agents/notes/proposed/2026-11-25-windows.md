# Agent Note: Windows

Status: proposed — Kaden on native Windows as Claude Code runs there: commands through Git Bash, no sandbox (every command asks outside the read-only ones), and Windows versions of the few POSIX-only calls

## Problem

Kaden runs on Linux and macOS only. Its shell tool, process control, instance lock,
single-window socket and two asyncio pipe readers assume a POSIX system. Windows is where
most desktop users are.

### What is POSIX-only today

| Where | What | On Windows |
|---|---|---|
| `runtime/instance.py:6,45,58` | `fcntl.flock` on the data folder's lock file | no `fcntl`; import fails, so Kaden does not start |
| `tools/shell_files/__init__.py:567` | `["sh", "-c", script]` | no `sh` unless Git Bash is installed and found |
| `tools/shell_files/__init__.py:564` | `pwd -P` in the script, to follow `cd` | works in Git Bash; the path is `/c/Users/…`, which needs converting back |
| `tools/shell_files/__init__.py:580` | `start_new_session=True` | ignored: no process group |
| `tools/shell_files/__init__.py:1044–1050` | `os.killpg(SIGTERM)`, then `SIGKILL` | no `killpg`; a command's children outlive Stop |
| `tools/shell_files/__init__.py:558,586–588` | `os.pipe()` read with `loop.connect_read_pipe` | not supported by the Proactor loop for `os.pipe` handles (CPython issue 26832) |
| `tools/shell_files/__init__.py:464,468,484,501,504` | `os.open` with `O_DIRECTORY`, `O_NOFOLLOW`, `O_NONBLOCK`, `dir_fd` walk (Read, Write, Edit) | none exist on Windows (`os.supports_dir_fd` is empty) |
| `tools/shell_files/__init__.py:924,1090,1219` | `os.fwalk(".", dir_fd=…)`, `os.stat(dir_fd=…)`, `os.open(O_NOFOLLOW \| O_NONBLOCK, dir_fd=…)` (Glob, Grep) | no `os.fwalk` on Windows; Glob and Grep fail |
| `tools/shell_files/sandbox.py:39–41` | bubblewrap or Seatbelt | neither: `find()` returns `None`, commands ask (safe as written) |
| `tools/shell_files/screen.py:71–74` | portal or `screencapture` | neither: the screenshot tool is not listed (safe as written; see below) |
| `runtime/hooks.py:45,49,67` | `create_subprocess_shell`, `start_new_session`, `killpg(SIGKILL)` | runs `cmd.exe`, not a POSIX shell; a hook's children outlive a timeout |
| `frontends/headless.py:97,99` | `connect_read_pipe` on stdin, `connect_write_pipe` on stdout | fails with WinError 6 (CPython issue 26832/43528); sub-sessions run their children headless over stdio, so sub-sessions fail too |
| `frontends/desktop/single.py:23,39,46` | `start_unix_server` / `open_unix_connection` | Unix only in asyncio |
| `frontends/desktop/app_menu.py:29` | Linux desktop entry | `supported()` is false (safe as written) |
| `__main__.py:488` | `Popen(start_new_session=True)` to hand over to the window | ignored; the window may close with the console |
| `runtime/review.py` | `protected`: paths matched with `/` and case-sensitively | `C:\Users\…\.kaden` and `c:/users/…` would not match |
| `api.py:1318–1343` | the read-only command check parses POSIX shell (`shlex`, posix) | right for Git Bash, which is what runs the command |

Fine as they are: `keyring` (Credential Manager), SQLite, `asyncio.create_subprocess_exec`
with `PIPE` (sub-sessions, MCP servers, git), Qt and Qt Multimedia, `~/.kaden`,
`os.dup2` in headless.

## Proposal

Match Claude Code on native Windows:

- **Git Bash runs the commands.** Claude Code needs Git for Windows and runs its Bash tool
  in Git Bash, found on `PATH` or named by `CLAUDE_CODE_GIT_BASH_PATH`. Kaden does the
  same: `bash.exe` from Git for Windows (found next to `git.exe`, or named by
  `KADEN_GIT_BASH_PATH`). Without it the shell tool is not offered, and Settings says
  to install Git for Windows. The script stays the same POSIX script; the folder it ends in
  (`pwd -P`, `/c/…`) is turned back into `C:\…` with `cygpath -w`.
- **No sandbox.** Claude Code's sandbox runs on macOS, Linux and WSL2, not native Windows
  ([its docs](https://code.claude.com/docs/en/sandboxing)). So on Windows every command
  that is not read-only asks, as on any system where `sandbox.find()` finds nothing.
  The read-only check and the automatic review work as everywhere else. WSL users can run
  the Linux build inside WSL2, with bubblewrap.
- **Ending commands: a Job Object.** Each command starts in a Windows Job Object with
  kill-on-close, the Windows way to end a process with everything it started.
  `_terminate_group` closes the job on Windows (after a grace period with
  `CTRL_BREAK_EVENT`, as SIGTERM). The same applies to hooks. The library is `pywin32`'s
  `win32job` (an established binding), Windows only by a marker in `pyproject.toml`.
- **Reading output: threads, not a pipe reader.** On Windows the shell reads its
  `os.pipe` with `asyncio.to_thread` reads into the same `_OutputBuffer`. Headless reads
  stdin and writes stdout the same way (a writer thread fed by a queue), which keeps
  sub-sessions working. One small reader with two implementations, chosen by `sys.platform`.
- **Lock: `msvcrt.locking`** on the lock file, the stdlib's Windows lock, behind
  `InstanceLock`.
- **Single window: Qt's local socket.** `QLocalServer`/`QLocalSocket`
  (named pipes on Windows, unix sockets elsewhere) replace the asyncio unix server on every
  system. The desktop already depends on Qt, and it keeps one code path. This changes macOS
  too: the single-window check of [macOS, the rest](2026-11-25-macos-the-rest.md) is run
  again on a Mac after it.
- **File tools: no `dir_fd` walk.** Read, Write and Edit open by a walk that refuses
  links at each step, and Glob and Grep walk with `os.fwalk`, so a file outside the
  workspace is never reached through one. On Windows Glob and Grep walk with `os.walk`
  (links to folders not followed, as now), and each file is checked as below. The check:
  resolve the path with `os.path.realpath` (which follows links and junctions on Windows),
  check it is in the workspace, open it, and compare the opened file's identity
  (`os.fstat` against `os.stat` of the resolved path). Slightly weaker (a race between open
  and check, for reparse points the user made), and stated in the docs.
- **Protected paths, case and separators.** `review.protected` normalizes both the call's
  text and the protected folders with `os.path.normcase` and matches `\` as well as `/`,
  and also Git Bash's form of each folder (`/c/Users/me/.kaden`, from `cygpath -u`), since
  the commands it judges run there.
- **Hooks run in Git Bash** (`bash -c`), as Claude Code's hooks do on Windows (its hooks
  fail there without Git Bash, per its issue tracker), so a hook written for Linux or macOS
  runs unchanged.
- **Screenshots: out of this note.** The tool is simply not listed on Windows, as on a
  Linux desktop without the portal. A Windows capture (e.g. Qt's `QScreen.grabWindow`, or
  the `mss` library) is a follow-up once the port runs.
- **Package: Briefcase's `.msi`** (WiX), built on GitHub's Windows runners. Signing comes
  later: Azure Artifact Signing (formerly Trusted Signing) is limited to organizations and
  individuals in the US and Canada, so it may not be open to the user. Unsigned, SmartScreen
  warns on first run.

## Alternatives considered

- **WSL2 only.** Kaden's Linux build already runs there with the sandbox, so no port is
  needed. But it is not a Windows app: no Start menu entry, no Windows keychain, files under
  `\\wsl$`, and WSL must be installed and enabled first.
- **PowerShell instead of Git Bash.** Built in, so no install. But the model writes POSIX
  shell far better, the read-only check parses POSIX syntax, and Claude Code chose Git
  Bash.
- **A Windows sandbox** (AppContainer, Windows Sandbox, a restricted token). AppContainer
  is the closest to Seatbelt, but nothing in Python wraps it, and Claude Code ships none. It
  would be Kaden's own security boundary. Later, if Claude Code adds one.
- **`psutil` to end process trees** (walk children, kill each). Already a dev dependency,
  but a child that starts after the walk escapes. A Job Object holds every descendant.
- **An asyncio reader on a named pipe made overlapped** (`_winapi.CreateNamedPipe`).
  Keeps everything on the loop, but uses CPython's private `_winapi`.

## Acceptance criteria

- `uv run pytest` passes on GitHub's `windows-latest` runner, with tests that need a
  sandbox or POSIX tools skipped by a marker that says why.
- On a Windows machine with Git for Windows: the app starts, saves a key, runs a command
  after asking, follows `cd` across commands, and Stop ends a command that started a child
  (`sleep 100 &`, `python -c "import time; time.sleep(100)"`).
- Without Git for Windows, the shell tool is missing and Settings says why.
- A second launch shows the first window.
- `type C:\Users\me\.kaden\config.toml` and `cat /c/Users/me/.kaden/config.toml` ask as
  protected.
- Glob and Grep find files in the workspace and do not follow a junction out of it.
- A sub-session starts and answers.

## Risks

- The biggest port so far: about ten places in four modules, each with a Windows twin
  to keep working. CI on Windows is the only guard for most of them.
- No sandbox means more prompts on Windows than on Linux or macOS, against the user's
  "the less it asks the better". It is what Claude Code does there.
- Git Bash path conversion (`/c/…`, MSYS argument mangling of `/foo` arguments) surprises
  programs; Claude Code has a run of issues about it.
- Voice: whether sherpa-onnx's Windows wheels cover Python 3.14 is unverified.

## Implementation plan

Files: `runtime/instance.py`, `runtime/hooks.py`, `runtime/review.py`,
`tools/shell_files/__init__.py`, `frontends/headless.py`, `frontends/desktop/single.py`,
`__main__.py`, `pyproject.toml` (pywin32 for Windows), `.github/workflows/test-windows.yml`,
`docs/` (install on Windows, what asks), `.agents/decisions.md`.

Tests first, each runnable on Linux with fakes where it can be:
1. `InstanceLock` refuses a second holder (exists), runs on Windows CI.
2. `single`: second launch reaches the first through `QLocalServer`, on every system.
3. Shell: the Git Bash finder (fake folders with `git.exe` and `bin/bash.exe`), the
   `cygpath` conversion, "no Git Bash" leaves the tool out.
4. Stop ends a command's child on Windows (Windows CI only).
5. `protected` matches backslash, case and `/c/…` variants (any system, as text).
6. Glob and Grep do not leave the workspace through a link (exists; runs on Windows CI).

Steps:
1. Add the Windows CI job, with everything failing shown; skip what must wait.
2. Lock, then single window (Qt local socket on all systems).
3. Output reader and headless stdin reader by thread on Windows.
4. Git Bash finding and path conversion; the shell tool on Windows.
5. Job Objects for commands and hooks.
6. File tools' Windows check.
7. `protected` normalization.
8. Briefcase `.msi` in the release workflow, unsigned.

Open questions for the user:
- Is WSL2-only enough to start with, or is a native Windows app the goal?
- Signing: are you in the US or Canada (Azure Artifact Signing), or should the `.msi`
  ship unsigned with SmartScreen's warning?
